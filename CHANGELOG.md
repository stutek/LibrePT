# LibrePT Changelog

Shipped changes, newest first. Backlog and open questions live in [TODO.md](TODO.md); a completed
backlog item graduates here as soon as it has shipped and passed the gate, leaving a one-line stub
behind so its `§N.M` number keeps resolving — those numbers are cited from `src/`, `tests/` and
`docs/`, so they are identifiers, not just headings.

Format follows [Keep a Changelog](https://keepachangelog.com): grouped into **Added**, **Changed**, **Fixed**.

## 2026-08-18 — A restore says what it does to the file, not just to the device

### Added
- **A crash becomes something a trainer can report** (TODO §12.4) — nothing installed `window.onerror` before this, so an exception died in a console a PT will never open while [BUG_REPORTING.md](docs/BUG_REPORTING.md) asked them to retype the build stamp by hand. Global `error` and `unhandledrejection` handlers now capture into a small in-memory log, and the notification feed offers a **prefilled GitHub issue** the trainer reads and submits themselves. **Non-identifying by construction**: a fixed field list — message, stack, route, build, time — with anything else a caller passes dropped, because a redaction pass that strips known-bad keys fails the first time someone adds a field nobody remembered to strip; a test hands it a client's name, notes and injury and asserts none of it can appear. The route travels because routes are durable and their ids are opaque (UC5), which makes the failing URL the best reproduction instruction there is. **Offered from the feed, never as a modal** — §12.4's own warning is that a handler rendering over a live session mid-set is worse than the original bug, and an e2e case asserts no dialog opens. Identical repeats collapse into one entry with a count, so a render loop cannot evict the report explaining how it started. **What it does not fix**: a PT without a GitHub account still has no route, which is §23.5's open item and a maintainer decision.
- **Forward-migration consent at import** (TODO §18.7's last open item) — restoring an older backup now says what the import does to the FILE, not only what it replaces on the device: the migration steps in plain words, then *"this brings the file's data forward, and it will no longer open in older builds of LibrePT"*. **The case it was missing was the empty device**, which skipped the prompt entirely — precisely where the replace warning has nothing to say while the one-way door still applies. Consent is asked when either consequence is real, and the two lines appear independently. Declining writes nothing at all, asserted on a clean device; a file already at this build's shape still restores in one step, so the ordinary case gained no toll. An existing test that asserted "an empty device never asks" was **rewritten rather than kept** — it used an old file, and that stopped being right the moment portability became something to lose.

## 2026-08-17 — Clients introduce themselves; a walkthrough that drives the real app

### Added
- **A changed session offers to tell the clients** (TODO §1.6) — moving a session's time or room asks once whether the people already invited should get the new details, names which detail moved, and on yes reopens the ordinary invite dialog for exactly those clients. Four triggers and no more (refined the same day): the slot, the room, the session's **kind** — leg strength becoming cardio, which changes how a client eats and what they bring, derived from the modalities its routine prescribes rather than stored — and the **invitee list**, since a one-to-one that becomes a group of five is a different offer. **A rename or a same-kind plan edit asks nothing**: a prompt that fires when a trainer fixes a typo is a prompt that gets dismissed on the change that mattered. Only clients who were invited AND are still participants are offered — an attendee added by hand was never sent anything, and quietly turning a time change into their first invitation is a different feature. Saying no sends nothing and leaves no dialog behind, because the trainer has decided to tell them another way. Resending refreshes `sentAt` and keeps the answer already given, which stays legible as "answered before this went out" precisely because both are UTC instants.
- **Invitations can expire** (TODO §1.6) — the trainer sets how many hours before a session replies close, and the cutoff **travels in the invite** as an absolute instant, because the client's device knows only what the invite told it. Past it, the reply page closes and points at the one route that still works: messaging the trainer. Three decisions: **derived, never stored** (nothing runs at the cutoff, so a stored `expired` would only become true if the app happened to be open); **advisory, and worded that way** (two devices, two clocks, no server — the page declines to send, nothing recalls a message in flight, and a late answer that arrives is still recorded, which is why there is no "late" flag and only a response time); and **0 means "no deadline", which is not the same as unset**, so a trainer who turns expiry off does not get it reinstated by a default. Exactly at the cutoff is still open — "four hours before" reads as "up to", and refusing that second would be a coin toss on clock skew.
- **An RSVP has somewhere to live, and staging is enforced for the first time** (TODO §1.6/§18.4) — the last leg of the invite loop: the trainer taps the link a client's reply carried, and the answer lands in their own store. Decided by the maintainer, and each ruling changed the shape:
  - **"Invites should host the RSVP status, sessions should host attendees list (by reference only for easier anonymization)"** — so `invites` is its own collection, and an RSVP is a fact about a message that was sent rather than a property of a person (who answers differently per session) or of a session (which has no single answer). `sessions.participants` stays authoritative, so ingestion **never touches it**: a "no" is an answer, not a withdrawal, and a client's reply must not silently remove someone the trainer put there. The record holds two ids and the facts about the message — no name, no contact — which is what makes anonymisation cheap: erasing a client leaves every invitation structurally valid with nothing in it to redact.
  - **"Not all attendees need an invitation, some will be added manually"** — an attendee with no invitation is the ordinary case, so nothing reads an absent invitation as "not coming".
  - **"No need for a special mark for late responses, just record response time"** — `answeredAt` and `sentAt` are both UTC instants, so the difference is correct across any pair of timezones. The timestamp convention is now written down: **instants are UTC, calendar dates are local** — "at" versus "on" — with the consent date as the case that proves it, since `toISOString()` there once filed a 00:30 signature as the previous day.
  - **"Not modifying [schema 4] would actually test our rollout plans"** — and it did. Declaring the first preview-only collection found that **nothing enforced staging**: the star-write fan-out wrote every projected record into every live store, and the backup file walked the projector table, which knows nothing about schemas. A preview-only shape would have landed in `schema4` and in every backup, undeclared — the exact failure staging exists to prevent, invisible until someone tried it. Now a record is written only to stores whose schema declares its collection, and a backup carries the collections of the schema it is written at. **The cost is accepted and now visible**: a restore replaces preview-only records with nothing, and the confirmation names them separately from everything else, because every other collection is *replaced* while these are simply *gone*.
- **A client can answer an invite, by text or by email** (TODO §1.6's confirm link; SMS ruled in by the maintainer — "let us have SMS too, for sure") — there is no server, so the answer travels as a message to the trainer whose body carries a LibrePT deep link the trainer taps once. Three things worth not re-deriving:
  - **A page, not two links in the invite body.** The original sketch put prefilled `mailto:`/`sms:` Confirm links straight in the invite. That works in an email and fails in a text: an `sms:` URI inside an SMS body is not linkified by most messaging apps, so the SMS leg — the one just ruled in — would have had no working route at all. Both invite channels carry a plain `https` link, so the reply URI is built on the page at tap time, once the client has chosen a channel.
  - **No new route was needed.** An invite link is already the app's own root with `?evt=`, so the boot decision turns on what the payload IS: an invite means the client is answering, an RSVP means the trainer is collecting one. Inventing `/rsvp` would have stranded links already sent.
  - **The reply names nobody.** It carries `{sessionId, clientId, answer}` — no client name, no session title, no location. A title like "Post-surgery rehab" would otherwise disclose a medical fact about a named person to every system the message passes through, and a reply crosses a carrier and comes to rest in two message histories. A test greps the encoded payload for each of those. The invite now carries `organizerPhone`, which is what makes a text reply possible at all: the client's device knows nothing about the trainer beyond what the invite told it.

  **The invite leg landed with it**: every invite carries the reply link, and a client with a phone number gets a **Text it** button beside the email one — a text cannot carry the `.ics`, so email keeps the calendar file and the text carries the link. The trainer's number is a third string on `trainerIdentity` (prefilled like the organizer email, and deliberately not validated: numbers are written a dozen ways, the app never dials it, and rejecting a real one is the expensive mistake). **Not yet closed**: a returning `?evt=<rsvp>` is still ignored, because `sessions` has nowhere to store an answer — see [TODO §1.6](TODO.md), where the storage choice is stated as a decision rather than assumed.
- **Client self-onboarding, end to end** (TODO §1.7/§26, [UC8](use_cases/uc8_client_self_onboarding.md)) — a prospective client opens `/intake` on their own phone, says who they are, ticks consent there, and shares the result; the trainer reads it and accepts. Nothing is typed twice and nothing passes through a server, because there is none. Both open questions were ruled on by the maintainer and both shaped the build:
  - **The submission travels as a FILE, not a link** ("use shares"). `navigator.share({ files })` puts it straight into the client's own mail or messaging app. Three consequences: nothing sensitive sits in a URL where it would rest in a carrier's logs and two message histories; the file is a **retainable artifact** carrying the wording version, language and date ticked, which is far better Art. 7(1) evidence than a query parameter; and with no size budget a signature or photo becomes possible later. This **retired §26.2's fragment codec unbuilt** — no URL payload means nothing to compress, and §19.2's URL-privacy question does not arise here at all. It declares **both** a media type (`application/vnd.librept.signup+json`) and a distinctive extension, because an Android intent routes on the type, an OS association on the extension, and email frequently relabels the type to `octet-stream` so only the extension survives that hop; the trailing `.json` keeps the file openable where no association exists, which is every desktop and iOS. **The download fallback is permanent, not temporary** — `canShare({files})` is false on every desktop browser and on iOS below 15, and a prospective client standing in a gym cannot be told to come back with a different phone — so it is a first-class button rather than an error path.
  - **Goals and injuries are the client's to offer** ("customer should provide goals and injuries if they decide to do so"). Optional at every level, and a blank field is **absent** from the record rather than stored as `""`, so a trainer can tell "chose not to say" from "not asked yet". Prose over 1000 characters is refused rather than truncated: a sentence that stops mid-clause reads as the client's own words, which is worse than a refusal when it describes an injury someone will program around.
  - **`/intake` is stateless by construction**, not by discipline — its own boot step (`appBoot.bootIntake`), so the client's device gets no database, no seed, no service worker, no first-run agreement, no splash hold, and no write of any kind (`initTheme` included, since it persists the theme). A flag threaded through the trainer's boot would have worked until the day one step was missed, and the failure would be a stranger's phone holding a LibrePT database. Pinned at two tiers: the medium test checks all three storage APIs are empty after a submission, the e2e test checks the boot **decision**, which the medium tier structurally cannot see.
  - **The review dialog is the trust boundary**, and there is deliberately no signature to check — signing needs a key exchange, which needs the server this project does not have. What makes a crafted file acceptable is that a human reads one record before it enters the register. Consent shows as **evidence** (when, which wording, which language) rather than a tick; dedupe is an **offer**, matched on email or phone and never on name, declinable because two people do share a number; an update assigns only what the client supplied, so a skipped box cannot wipe a trainer's own note; and declining discards the parsed submission rather than leaving it primed for a later stray tap.
- **The guided walkthrough** (TODO §9.5, with §9.4) — see the entry below; shipped the same day.

### Fixed
- **The app menu ran off the bottom of the screen** — `.session-menu` had no height cap and no scroll, so as items accumulated everything below the fold became untappable, with nothing on screen to say so (AGENT_RULES §2.D.1: on a phone, unreachable is the same as absent). It now caps to the space under the header and scrolls, using `dvh` rather than `vh` because mobile Safari's `vh` includes the retracted URL bar — exactly the strip a bottom item would hide behind — and `overscroll-behavior: contain` so a flick inside the menu does not scroll the dashboard underneath it. Surfaced by adding one menu item, which pushed `#menu-terms` out of the viewport and failed an existing medium test; the new test pins the *property* (every item reachable at 390x844) rather than the item count that happened to fit.
- **A share button that could not share** — the intake page's send button set `hidden` and stayed on screen, because every `.btn` in this app declares `display: flex`, which beats the UA stylesheet's `[hidden]` rule. Every device that cannot share a file (all desktops, iOS below 15) would have been offered a button that throws. Found by a medium test **written before the wiring**, which is now [AGENT_RULES §5.10](AGENT_RULES.md); an after-the-fact browser probe had already reported the page working.

## 2026-08-17 — A guided walkthrough, and the last unbuilt promise is kept

### Added
- **The guided walkthrough ships** (TODO §9.5, with §9.4) — `?demo=walkthrough`, and the splash's own `#splash-walkthrough` button, which was **disabled and marked "soon" until today**: the last control in the app announcing something that did not exist. It explains one step at a time over the real app, with **Back / "Show me" / Next**. Four decisions worth not re-deriving:
  - **One script, not two.** It plays the same [gymFloorTour.js](src/modules/demo/gymFloorTour.js) the automatic demo plays, through the same `performStep` tap. A second script would be a second thing that has to stay true of the app — exactly the drift §23.5 chose a script over a screen recording to avoid — and the demo's e2e replay already keeps this one honest.
  - **The trainer doing the step themselves is what advances it.** Completion is the step's own expectation becoming true, watched on a poll, so it does not care who caused it: no scrim, no backdrop, the app fully tappable underneath. A walkthrough that only advanced on its own buttons would be teaching its own buttons. "Show me" is the escape hatch for someone who cannot find the control, and it withdraws once the step is done, because an offer to do something already done is a control that does nothing.
  - **A step cannot be skipped, and that is the app's constraint rather than a teaching choice** — there is no circuit card before the clipboard is open and no Too Easy button before a card is in focus, so a Next that worked before the step happened would point at nothing.
  - **Back re-explains; it does not undo.** An inverse for every step is an undo stack for a demonstration. A step returned to stays done, so re-reading what Too Easy meant cannot log a second signal — and leaving is one tap that keeps whatever the trainer already did.

  The panel **moves to the top of the screen when it would cover the control it is pointing at**: a guide that hides the thing it is highlighting is worse than no guide on a phone, where there is nowhere else to look. The pure cursor is [domain/walkthrough.js](src/domain/walkthrough.js) (7 `node:test` cases); [tests/e2e/test_walkthrough.py](tests/e2e/test_walkthrough.py) drives the real controls, including a case that pins the caption is **translated copy and not an i18n key** — a missing translation renders the key itself, which is invisible to every other test and is the first thing a trainer would read.

### Changed
- **The landing page offers three doors instead of two** (TODO §23.5) — watch it drive itself, walk through it with the guide, or poke at the sample gym unguided. The middle one is what a trainer who liked the video but does not want to be dropped into an unfamiliar app actually needs.

## 2026-08-13 — The demo feed stops promising what the app cannot do

### Changed
- **The demo notification's buttons do what they say** (TODO §9.5) — "Explore Walkthrough" offered the unbuilt guided walkthrough and navigated to the client list; "Open Live Demo" linked to the app's own public URL from *inside* the running app, which is a reload on the hosted origin and a jump into a stranger's instance from any other, dead without signal either way; "About demo data" sent a trainer with no GitHub account to a README on `github.com`. The walkthrough is now announced in exactly one place — the splash's disabled, "soon"-marked `#splash-walkthrough`, where a first-run user is choosing how to start — rather than twice, once honestly and once not. The README link was **dropped rather than repointed at a rendered page** ([TODO §3.12](TODO.md) left it here for the decision): the cleanup screen it sat beside already itemises what counts as demo data and what survives, so the link led to a worse copy of a screen one tap away.
- **An empty feed means two opposite things, and now renders as two** — a database with nothing in it gets the offer to seed the sample gym; a database with a real gym in it and nothing outstanding gets "you're all caught up", a pair of strings that had been defined in both locales and used nowhere since the branch that would show them did not exist. One card served both, so a trainer with ten real clients was told their "workspace is preloaded with live training data" and given a button that would have written the demo dataset in among their records — under the label "Open Live Demo", which reads as navigation. The seeder is now an injected `seedDemoData` rather than a `window.seedMockData` reached out of the global scope: **a global is not an import**, so `agent_tools/import_layers.py` could not see that a `modules/common/` component was calling into the app entry point, and nothing else said so either.

## 2026-08-12 — Drive sync works for real users; the counter stops lying; docs come in-app

### Added
- **A withdrawal is recorded, not erased** (TODO §27.7, Art. 7(1)) — §27.4 gave the client a way to withdraw; this gives the trainer somewhere to put it. The only action available before was unticking the consent box, which wrote `consentDate`, `formVersion` and `formLang` **blank** — so honouring a withdrawal destroyed the evidence that consent had ever been given, at exactly the moment a supervisory authority would ask for it. Unticking now records a `withdrawnDate` and keeps all three. `cloudSync` stays the single "may I process?" flag every caller already reads, rather than gaining a rival some branch would miss; re-ticking drops the withdrawal date, because signing again is a new consent and not an undo. **Never-consented and withdrawn now render as different states** in the profile badge and in the client's own Art. 15 export — the subject reading it is the person most entitled to see their withdrawal was acted on. Needed **no schema bump**: `gdprConsent` is an unconstrained object. The archiving dialog was also corrected — it told trainers to *delete the client's records* on withdrawal, conflating Art. 7(3) with Art. 17 and losing the withdrawal record too; withdrawal halts processing, erasure is a separate request the client makes.
- **Withdrawing consent is now the same reply that gave it** (TODO §27.4, Art. 7(3)) — the letter already told a client they *could* withdraw "at any time and in any form", which is the information requirement, not the route. Consent is given by replying **"I CONSENT"** / **"PRIVOLIM"**; withdrawal is replying **"WITHDRAW"** / **"PREKLICUJEM"** to the same message. The symmetry *is* the legal standard — withdrawal must be as easy as consent, and the same reply to the same person is exactly as easy rather than merely possible. **No stored trainer contact was needed, and deliberately none was added**: the letter reaches the client *from* the trainer's own address, since a `mailto:` opens the trainer's mail client, so reply is already one-tap and survives them changing address — a stored address would have been a second thing to keep correct for no gain. Carried in **both** channels, because a client sent the short SMS variant never receives the email letter. `CONSENT_FORM_VERSION` **not** bumped, on the 2026-08-10 precedent: purposes, recipients, retention and rights are unchanged, and making an existing right easier to exercise does not make earlier consent cover less — a bump would have asked every signed client to re-sign for nothing. What it does *not* yet do is **record** the withdrawal (§27.7): `gdprConsent` has no withdrawal state, so acting on the reply means unticking a box, which leaves a record indistinguishable from a client who never consented.
- **A real OAuth client id** (TODO §3.3) — Drive sync had been fully built since 2026-08-02 and worked for nobody, because `GOOGLE_DRIVE_CLIENT_ID` was blank and every deployment reported "not configured". **Not a one-line change**: the blank id was load-bearing in the suite, and `tests/medium/test_drive_sync_ui.py` pinned the unconfigured card, a state now unreachable. It pins configured-but-not-connected instead — Connect live, and neither Disconnect nor the interval control offered, since either would imply a session this device has never had. The **connected** state stays out of reach of every Playwright tier permanently: Google fingerprints and blocks automated browsers on `accounts.google.com`, which is what [tests/live/](tests/live/) exists for. The app is in Google's *Testing* status, so only listed accounts (≤100) can grant; demo users are unaffected, since `?init=demo_data_load` never contacts Google.
- **The privacy policy ships as a page, not a GitHub link** (TODO §3.12) — [render_docs.py](agent_tools/render_docs.py) generates `src/privacy.html` from the canonical `PRIVACY.md`, gated for drift in Stage 1. Two problems, one fix: five in-app links pointed at `github.com`, aimed at people who will never have a GitHub account and **dead without signal** — a defect in an offline-first app on its own — and OAuth verification requires the policy on a domain we can prove we own, which `github.com` is not. Markdown stays canonical and stays in the doc graph (AGENT_RULES §5.6 keeps `.md` out of `src/`); only the generated page ships, so the version Google reviewed and the version we edited cannot diverge. **markdown-it-py with `html=False` passed explicitly**, not inherited — markdown-it's `commonmark` preset *enables* raw HTML, and a version bump must not be able to silently reopen passthrough on pages that ship under an integrity catalog. The page shell carries `default-src 'none'` and loads no scripts, so it needs no `'unsafe-inline'` for styles — stricter than the app's own CSP can be.
- **Sync state has a vocabulary, and the header cloud speaks it** (TODO §3.11) — `↑!` past nine for AHEAD only, since those edits exist solely on this device; **behind keeps `↓↓`**, because Drive holding changes not pulled yet puts nothing at risk, and using one stand-in for both flattened the distinction. The cloud's overlay is state-driven: spinning arrows syncing, a warning triangle on failure, a muted slash when not connected — **informational, not a fault**, because [PRIVACY.md](PRIVACY.md) makes local-first a supported choice and the warning colour is reserved for a real failure and §3.8's hazard. Motion is Font Awesome's own `fa-spin`, whose stylesheet already cuts it under `prefers-reduced-motion`, so the guard cannot drift from what it guards. The mapping is a DOM-free module, which forces every state to carry a **label** as well as a shape: the glyph is `aria-hidden`, so without words in the button's `aria-label` the state would be unreachable on touch and silent to a screen reader.
- **Tapping the header cloud syncs** (TODO §3.11) — the dialog stays in the ☰ menu. It and the sync were two independent listeners on `#backup-btn`, each correct alone, so a connected tap did both; there is one now, and `backupRestore` opens the dialog only for taps `driveSyncUi` declines. Conflicts still open the review modal, and a failure posts to the notification feed — **synthetic, never stored in `state.notifications`**, or it would ride into the backup file and the Drive snapshot and count as a local change, so a failed sync would increment the very ahead counter it failed to clear.

### Changed
- **The ahead counter counts everything when nothing has ever synced** (TODO §3.9) — adding a circuit left it at 0. Every link worked; `getAheadCount()` short-circuited to 0 whenever there was no ancestor, and an ancestor only exists after a completed sync. That was defensible exactly as long as no deployment had a client id: "never synced" was universal and a 0 misled no one. The moment one shipped, **"connected but never synced" became reachable, and there a 0 reads as "everything is backed up" while nothing is.** The same answer is right for a trainer who never connects — treating silence as an informed choice to stay local-only is a guess whose cost is every client record lost to a cache clear.
- **`recordBackupTaken()` / `readBackupHistory()`**, written by both a completed sync and a downloaded JSON backup (TODO §3.8's input). Its own meta key, **not** a field on `driveSync`, whose ancestor is merge-critical: a three-way merge is only correct if the ancestor is exactly what Drive last saw, so an export writing there would corrupt the next merge. Deliberately **not** consumed by the ahead count — that arrow is Drive-relative, so a file backup does not reduce it and should not, while §3.8's warning is backup-relative. Keeping them apart is what lets the count stay factual while the warning stays honest; if only a Drive sync could clear a safety warning, it would be a growth prompt in a warning colour.
- **Sync counters are legible** (TODO §3.11) — they shipped at 10px with 9px arrows, which is AGENT_RULES §2.D's own stated anti-pattern ("9px of text is nothing to aim at"), in the surface a trainer checks to learn whether their work is safe. Raised at every viewport, since a phone at arm's length mid-session is the harder read; desktop gets a further step (76px header, 14px counters) on `(min-width: 700px) and (pointer: fine)` — width alone would be wrong, because a phone in landscape clears 700px and is exactly where vertical space is scarcest. Height is the only axis available at all: the app body is a 480px centred column at every width.
- **ZAP suppressions get audited, not just counted** ([AGENT_RULES §2.A.3](AGENT_RULES.md)) — `WARN-NEW: 0` counts only what the ignore file does not already silence, so a clean run says nothing about the seven suppressed rules. Every `IGNORE` now carries a `RE-CHECK` clause stating an invalidating **condition**, not a date, because a date expires silently while "if this file moves to that flow" is checkable by whoever next touches it. Rule `10202` proved the point: its note said "re-verify once the Google OAuth integration ships", it had shipped that afternoon, and the trigger surfaced only because the maintainer asked what the skips were.

### Fixed
- **A dead grant says "reconnect", not "sync failed"** (TODO §3.3) — a revoked or expired token surfaced as a generic failure, leaving the only available action tapping Sync Now on a session that could never succeed. The classification has to happen at the HTTP status because **a Google access token is opaque**: `ya29.` strings are not JWTs, so `expires_in` at grant time is the only expiry signal and the computed expiry is a guess. A token dies early whenever the trainer revokes at `myaccount.google.com`, the password changes, or the clock is skewed — and the sole evidence is the status on the failing call. `driveFetch` now throws a `DriveApiError` carrying it; `isAuthFailure()` reads 401, plus 403 **only** when the reason mentions scope, since a quota 403 is transient and disconnecting a trainer over one would be actively wrong. On that failure the stored consent is forgotten, or `hasStoredConsent()` keeps reporting "connected" off a flag Google already invalidated.
- **Consent-time refusal is separated from cancellation.** Both arrive from Google Identity Services as the same `access_denied`, so `googleAuth` records whether the attempt was interactive. This matters immediately: in *Testing*, only listed test users can grant, and everyone else is refused having done nothing wrong. They are told exactly that, with the reassurance their data is safe locally. The copy deliberately avoids "preview mode" — that phrase already means the **data-loss** warning in this app, and collapsing the two would blunt the more important one.

## 2026-08-11 — Two data-subject rights get code; backups any build can open; consent on paper

### Added
- **Erasure, as anonymization rather than deletion** (TODO §17.3, §27.1) — identity is replaced with a pseudonym **derived from the record's own opaque id**, and the execution records stay. That settles §17.3's open question as **irreversible**: a reversible scheme needs a mapping, and with no server the mapping would live in the database it protects — one file that un-erases everyone. Deriving the pseudonym means nothing extra is stored to reverse. It fans out to `clientName` denormalised onto history and planUpdates (the exact "one store keeps the name" failure [DATA_MODEL §5](docs/DATA_MODEL.md) warns about) and to trainer-typed prose no schema marks as identifying. Body-weight history is cleared with the name — **a body weight measures the person, a session load measures the work**; consent survives, because it names nobody and is the Art. 7(1) evidence that everything before was lawful. **Two Jane Does is ordinary in a gym**, and is where a name-based sweep does real damage: prose in records the client *owns* is rewritten, but text several clients share — a session title — is left exactly as typed and reported for a human pass. Both dialogs identify their target by alias/email/phone/joined/id-tail rather than by name, and the erase dialog names the *other* Jane so a trainer with the wrong record open can notice. An erasure that reports "done" is a lie of omission, so the receipt itemises the surfaces it cannot reach and why: the gym calendar (automatic once §1.5 lands), sent mail and SMS (never — a `mailto:` hands the draft to the trainer's own client and forgets it), old backup files, and the signed consent form, which must deliberately be **kept**.
- **A register of erasures that survives a restore** (TODO §18.11, §27.3) — erasing rewrites the live database, but yesterday's backup still names them, and §18.7 wants backups restorable indefinitely, so "old files rotate out" is not a defence. Salted id hashes, applied **at import** and re-anonymising on the way in, before the data becomes live. It has to survive a reinstall, so it travels inside backup files and is **unioned** on import, never replaced — a file is one moment, and adopting its copy would drop every erasure made since. That forced a **fresh salt per entry**, since one install-wide salt cannot be merged across devices; the side effect is strictly better, because duplicates become unscannable.
- **A per-client export, encrypted** (TODO §27.2) — whitelist-scoped to one client, so the worst mistake this surface can make (handing one client another's health data) is structurally hard rather than a filter that might miss. A group session is disclosed as a **size, never a roster**. The trainer's own notes **are** disclosed — an assessment about a person is that person's data — and the dialog's notes box exists for Art. 15(4), removing a third party from a note, with any redaction *declared in the file* rather than silently applied. AES-GCM-256 over PBKDF2-SHA-256 (600k), because email is plaintext-at-rest and this is one person's complete health record. The limit is stated on screen rather than papered over: **a `mailto:` cannot attach a file on any platform**, so the flow is download → compose → attach yourself, with the passphrase sent separately by SMS and generated as readable words because it gets dictated over a phone. The client's half is an app-menu dialog that decrypts on their own device with no install and no upload — an attachment nobody can open is worse than no export at all.
- **The trainer-facing privacy doc now describes buttons that exist** (TODO §27.5) — [PRIVACY_FOR_TRAINERS.md §5](docs/PRIVACY_FOR_TRAINERS.md) tabulated four data-subject rights against "what to do in LibrePT", and two of the four named actions had no code behind them. A compliance document naming a button that does not exist is worse than one saying "do this by hand", because the trainer discovers the gap while a statutory clock is running.
- **Paper GDPR consent, per client and per language** (TODO §3.5) — a *Data Protection* fieldset in the Add/Edit Client dialog with an **editable signed date**, a **versioned letter** (`gdprConsent.formVersion`, a full ISO date: consent is consent to a *wording*, and without the stamp there is no way to answer "who is still covered?" after the text changes), and email **and SMS** delivery through the device's own apps. The client documents live per locale in [src/i18n/consent/](src/i18n/consent/index.js) with printable editions in `docs/templates/<lang>/`, and the language is chosen **per client** (`gdprConsent.formLang`) — a Slovenian trainer with one expat client must be able to send that one client an English form without switching the whole app. One version spans all languages, because translations state the same promises. The archiving reminder is a **dialog, not a tooltip**: LibrePT stores no signature, so the trainer holding the paper is the whole evidence chain and cannot be told so only on hover.
- **Backups are written at a stable numbered schema** (TODO §18.7) — the export was a raw `JSON.stringify(getState())`, so it dumped whatever shape the runtime happened to have, restorable only by the exact build that produced it. Files now project through `STABLE_SCHEMA` using the same projection path the star-write fan-out uses, so the file cannot drift from what the store would write. **ONE shape per file**: expand-first staging (TODO §18.4) makes the newest numbered shape a strict superset of every older one, so an older copy alongside it would store strictly less information at full size — a test asserts that superset rather than trusting the convention. Files carry `exportedAt` (a temporal anchor, so a migration deriving dates does not reach for `new Date()` and date a two-year-old backup as today) and `buildSha` as a support breadcrumb. The cost — a preview-only field does not reach the file — is stated in the UI in a full sentence, not an icon, because the gap is not guessable from a symbol.
- **A frozen backup corpus** (TODO §18.7) — five committed fixtures, schema 0 through 4, each asserted to still import to the expected domain object, plus restore tests driving the real import UI at every version a backup can arrive at. Without it "restorable indefinitely" is a hope.
- **A confirmation before a restore replaces real data** (TODO §18.7) — a restore *replaces*, which is the right semantic (merging two databases needs a common ancestor, which Drive sync's three-way merge has and a file import does not), but it was silent: a trainer setting up a new phone who had already entered a client lost it with no warning. The prompt **names what would be lost per collection** ("8 clients, 13 sessions" is a sentence they can weigh, "Are you sure?" is not) and appears only when something is at stake, because a warning shown every time is a warning nobody reads.
- **Selective demo-data removal** (TODO §9.3, [UC7](use_cases/uc7_demo_to_clean_database.md)) — the demo notice's primary action called `resetLibrePTData()`, deleting the **whole database**, which was fine while the only person pressing it had nothing else and destructive from the moment a trainer added real clients. It is now a confirmation **screen** rather than a `confirm()`, because the one case the planner cannot rule out is per-record — a seed record the trainer edited into something of their own — and a `confirm()` offers one bit for a decision that is per-record. Provenance is **never inferred from id shape**; the seeded exercise catalog is an asset, not a stain, and is kept with the reason shown on its own line rather than in a tooltip.
- **A geometry gate** (TODO §25) — every test asserted semantics (text, counts, ids) and none asserted geometry, so a control running off the screen edge, or one silently clipped inside its own box, passed the whole gate. [`overflow_scan.py`](agent_tools/overflow_scan.py) sweeps two invariants (nothing past its nearest **clipping ancestor**; nothing clipped inside its own box) across iPhone 14, Galaxy S23 Ultra and desktop, plus one Slovenian pass at the narrowest width, since overflow is a text-length bug. **The mechanic worth knowing**: `body { overflow-x: hidden }` already masks the whole class from any root-level `scrollWidth` check, so the check has to be geometric and per-element. Router-driven `pushState` walks ~20 routes on one cold boot. No allowlist — intentional clipping opts out in the markup as `data-clip="intentional"`. **Three false positives came first, each buying a rule now stated in the tool**, and the last is the one to remember: *"wholly outside its box" is benign only for elements positioned OUT OF FLOW* — a parked drawer sits outside on purpose, but in-flow content outside its clipping box has been deleted, not truncated. Exempting it unconditionally reported the wide phone and let the narrow, worse case through.
- **A live Google canary on a bounded stored credential** (TODO §1.5.1) — the hermetic suites pin our request shapes and structurally cannot see Google deprecating an endpoint or reclassifying a scope. **Two attempts at storing no secret came first, and the wall they hit is the thing to carry forward**: Workload Identity Federation can only ever mint a *service account* token, and Google refuses a service account's `appDataFolder` writes for lack of storage quota — so the half of the canary that matters most could not run keylessly at any price. It now carries a real account's refresh token as an Actions secret, bounded by a consent screen set to **In production** (valid until revoked, changed, or six months unused — not the 7-day expiry Testing mode forces) and by production's own two scopes. Deliberately **not** a deploy gate: gating a release on a third party's uptime blocks a deploy for an outage no change of ours caused and no revert can fix. **The stored secret is no longer the thing to forbid — leaking it is, and so is a canary reporting confidence it has not earned**: tests enforce no `pull_request_target`, the credential read from `secrets.` and never `vars.` (a variable is world-readable and prints in plain text), both *derived* fields masked (`refresh_token` and `client_secret` are what a `set -x` would dump, and neither matches the blob byte-for-byte, so neither is masked automatically), and a missing credential failing the run **before checkout** rather than passing green having watched nothing. The scope check could not survive the move — the grant lives on a consent screen now, not in workflow YAML — so it became [`tokenScopes.live.test.mjs`](tests/live/tokenScopes.live.test.mjs), asking `tokeninfo` what the token was *actually* granted; strictly better, since it also catches an over-broad grant that would keep every Drive test green while production's narrow `drive.appdata` was broken.

### Changed
- **One numbering axis for record schemas and the migration chain** (TODO §18.14) — the two used small integers for different things (`{2, 3}` versus `1–4` plus `P`), so "schema 3" meant one thing in `recordSchemas.js` and another in `migrationSteps.js`. `LIVE_SCHEMAS` is now `{4, P}` and 4 is the same 4 the chain ends at. The two live shapes do different jobs and **only one is durable**: `schema4` is what a backup is written at and what `P` is rebuilt *from*; `schemaP` is the shape this build reads, disposable, its fields free to change on any commit. `P` is rebuilt whenever the recorded build SHA does not match the running one, and an **absent** marker counts as not matching — "we don't know which build wrote this" resolves to the branch costing a projection pass, not the one risking a read of fields that are not there. `"P"` is deliberately not a number: a fraction in stored data reads as a real schema version to anyone inspecting a database.
- **Prose-only commits are exempt from the full gate** ([AGENT_RULES §2.A.3](AGENT_RULES.md)) — a one-paragraph TODO edit cost a 2m02s run of lint, Node tests, a `pip-audit`, two browser suites and a ZAP scan to verify Markdown not one of them can observe. The boundary is drawn at **prose**, deliberately not at "docs": `docs/SRC_MODULES.md` is parsed by `catalog_coverage.py`, `INDEX` files are parsed by their tools, and a mixed code+doc commit is a code commit.

### Fixed
- **The v1→v2 migration dropped `bookings` instead of renaming them.** `bookings` was *renamed* to `sessions` — the same records, the same shape — and the step dropped them anyway, on the reasoning that pre-release data was not worth protecting. **That reasoning has expired**: preview instances are demoed on real trainers' devices and backups arrive from every version 1–4, so a database still carrying `bookings` lost its entire schedule. Also restored the per-version chain that a previous commit collapsed, and `detectSchemaVersion` now honours any version at or above the floor at face value — reading a stored 4 as "start over" is precisely what re-asked a language question the trainer had already settled.
- **The ellipsis deleted half the edit-mode title bar** (TODO §25.5) — `#session-title-text` is `white-space: nowrap; text-overflow: ellipsis`, **and an ellipsis eats whole ELEMENTS**, so on a 390px phone the edit-mode status chip sat 169px outside the box, entirely invisible, with no "…" to say anything was missing. It is the only thing on screen distinguishing editing a LIVE session from a future one. **Reordering does not fix that, it only chooses the casualty** — moving the chip first made the client name vanish by the same 169px, which the new sweep caught on the very next run. The fix is structural: a flex row where the chip and the "Editing" label declare `flex: 0 0 auto` and only the client name shrinks, with `min-width: 0` doing the actual work (a flex item's default `min-width: auto` refuses to shrink below its content).
- **Fresh demo data opened on sessions six hours past.** The seed anchored every "today" session with a `min(17, max(3, hour))` clamp that stops following the clock after 17:00, so an evening load opened on a wall of past sessions counting down in negative hours — the opposite of what the dataset is for. Slots now follow the real hour and may cross midnight, and each session's `day` bucket is **derived** from the timestamp rather than asserted alongside it, so the two can no longer disagree. Separately, any card left open past its start printed a negative countdown: the magnitude is now unsigned and the **label** carries the sense, flipping to "Overdue" via a CSS class the existing 1s ticker toggles rather than re-rendering a card under a trainer's thumb mid-set.
- **A `NaN` star-write target, caught by e2e rather than reasoned about** — `Object.keys(LIVE_SCHEMAS).map(Number)` produced `[4, NaN]` once a schema key stopped being numeric, so every write targeted a `schemaNaN` store that does not exist and 139 of 141 e2e tests failed on a splash timeout. Non-numeric schema keys are threaded, never coerced.

## 2026-08-05 — Test tiers, the `activeSession` contract, and the real cause of the `Page.goto` stalls

### Added
- **`tests/medium/`, a component tier** (TODO §20) — each test mounts ONE component via an `src/appBoot.js` boot step against real `index.html` markup, with the real `app.js` request intercepted and replaced: no router, IndexedDB, service worker or demo seed. The blocker had been that `activeSession` had no written contract — constructed in two places, consumed across a dozen modules, written down nowhere — so the only reliable way to obtain a valid one was to drive the real flow, which is why 68 of 138 e2e tests were the clipboard. The contract is now `active_session_fixture()` in [`tests/medium/_harness.py`](tests/medium/_harness.py) and [DATA_MODEL §7](docs/DATA_MODEL.md); 26 tests moved down a tier.
- **`tests/unit_js/`, a Node tier** (TODO §12.8) — pure-logic tests used to boot a full Playwright page because a browser was the only JS runtime this project had (the app's CSP forbids `new Function`, so there was no in-process eval harness; Node's own `import()` never touches a page). The dependency worry was **resolved rather than accepted**: no npm dependency at all — `node:test`/`node:assert` are built into the runtime — and Node is vendored the same pinned, checksum-verified way as Biome, so there is still no `package.json`.
- **An import-layer gate** ([`import_layers.py`](agent_tools/import_layers.py)) enforcing `data/` → `domain/` → `modules/common/` → `modules/<feature>/` → `controllers/` → `app.js`. Cross-feature imports are deliberately allowed (three exist, each a genuine composition); importing *up* a layer is not, because that is what costs a module its independent mountability. It found two inversions on its first run, both fixed rather than exempted.

### Changed
- **Font Awesome is vendored locally** (TODO §12.6) — the last CDN dependency, and **the root cause of the `Page.goto` stalls** (TODO §21): `page.goto` waits for `load`, `load` waits for every stylesheet, and that stylesheet was a live internet request made by every test in every tier — 1948ms median, 35233ms worst under 8 parallel contexts, with the goto maximum (35.61s) tracking the CDN maximum (35.23s) almost exactly. Days of chasing the local server, the listen backlog, CPU and the service worker were looking at things that were never involved, because the slow request never touched them. Also removed ZAP suppression 90003 (SRI Missing), whose entire justification was this stylesheet.
- **Artifact capture dropped from the gated run** — not tracing, not video, and not screenshots. Any artifact option activates pytest-playwright's per-test recorder around every browser context. Screenshots had survived on the claim that `--screenshot=only-on-failure` is "essentially free at collection time"; measured, that was false — **~40s of a 175s stage (~23%) on a fully green run**, where by definition not one screenshot is written. Escalate on demand instead (`--screenshot=on` on one node id).
- **A failing e2e test now fails the build, with no automatic re-run.** The old serial re-run forgave failures on the theory that xdist port contention produced spurious timeouts; it masked a genuine app-level async race (two uncoordinated `requestAnimationFrame` callbacks stomping each other's result) that went unnoticed for a while. "Passed on retry" is never evidence a test is reliable.

### Fixed
- **Every card in a re-rendered client grid threw on tap** (TODO §22) — `clientFormsController.js` re-rendered the list without `navigateToPath`, which had never been threaded in at all.
- **`#btn-sync-data`'s handler moved to the module that owns its markup.** Both defects hid behind the same thing: **a stub that hand-duplicates production wiring will agree with itself and disagree with the app.** Mount the real `bootXyz` step, or the test proves only that the test is self-consistent.

### Ruled out by measurement — do not re-derive
- The service worker (disabling registration made it *worse*: 38.3s → 52.7s wall; a `page.route` stub cost 59 failures in 702s because interception routes every request through the Node driver); dev-server throughput (2791 req/s); the TCP listen backlog (`Recv-Q` sampled at 0 throughout); host CPU (peak 2.4 of 16 cores); and CPU governor (`power-saver` costs ~21%, worth clearing, but fixes nothing). Run-to-run variance was ~3x and **will** fool a single measurement — two conclusions drawn from single runs during this investigation turned out wrong.

### Added
- **Google Drive `appDataFolder` sync** (TODO §3.3) — [`driveSyncConfig.js`](src/data/driveSyncConfig.js), [`googleAuth.js`](src/data/googleAuth.js), [`driveAppData.js`](src/data/driveAppData.js), [`syncMerge.js`](src/data/syncMerge.js), [`driveSyncService.js`](src/data/driveSyncService.js), UI in [`driveSyncUi.js`](src/modules/common/driveSyncUi.js). Decisions worth not re-litigating: **no visible, human-editable Drive file, ever** (`appDataFolder`'s invisibility is what makes the PII isolation of TODO §1.5 hold; a visible file needs the broader `drive.file`/`drive` scope every PT would re-consent to, for a convenience view with no safe editing UI — the escape hatch is the existing Export/Import JSON backup); **merge is a per-record three-way merge against the last-synced ancestor**, never wall-clock last-write-wins, which is why it needs **no Lamport `(deviceId, seq)` pair** despite TODO §18.5 anticipating one and **no tombstones** (the remote snapshot is always freshly downloaded and Drive's history is linear, so absence from a fresh fetch *is* the deletion signal — what would invalidate both: anything else ever writing the same file). Not built: incremental sync via the Drive Changes API; every pass moves the whole file. **`GOOGLE_DRIVE_CLIENT_ID` was blank** at first release, a supported "not configured" state; a real client id was installed 2026-08-12, and the OAuth app remains in *Testing*, so only explicitly-listed accounts (≤100) can complete a grant. Live-OAuth behaviour is still untested in CI by design — Google fingerprints and blocks automated browsers on the consent screen, so no Playwright tier can ever reach it — and the suite pins merge logic and request shapes against an injected `fetchImpl`, with [tests/live/](tests/live/) covering the real API separately.
- **The star-write CD gate** (TODO §18.13) — the properties this layer relies on are all *invariants across releases*, which is what a per-commit gate can hold and review cannot, because none can ever be tested against a real PT's data (that data is local-only by design). Asserted roughly in order of how expensive the failure is: the staging guard, projection round-trips, the old-UI-writes case, the acyclic reference graph, the frozen backup corpus, migration edge-case robustness, ordering invariants. Two places use a hand-authored hostile-input table rather than property-based fuzzing — a deliberate trade-off in this dependency-light stack, recorded so it is not mistaken for an oversight.

### Changed
- **`stateStore`'s read/write path moved onto IndexedDB** (TODO §18.6) — [`indexedDb.js`](src/data/indexedDb.js) (one database, one store per schema, three indexes), [`writeQueue.js`](src/data/writeQueue.js) (write-behind, ordered) and [`storageDurability.js`](src/data/storageDurability.js) (`persist()`). **+0 KB install cost** — it is the platform. Not SQLite-wasm: +700 KB–1.2 MB roughly doubles `src/`, and the OPFS `SharedArrayBuffer` VFS wants COOP/COEP headers GitHub Pages cannot set. **The layout constraint that decided it**: one database with one object store per schema, so a fan-out is a single transaction — IndexedDB transactions cannot span *databases*, so a database-per-schema layout makes atomic fan-out impossible by construction and is expensive to retrofit. `navigator.storage.persist()` is mandatory, not optional: without it IndexedDB is evictable and this app holds the only copy of a PT's business records.
- **Multi-version hosting retired from the code** (TODO §16.5) — deleted rather than adapted, since none of it had a subject any more: `releaseIdentity.js`, `versionCatalog.js`, `versionMessages.js`, `build/releases.py`, the release-publishing deploy step, and five test files. **Kept**: the commit-SHA build stamp and the build-info dialog — support surfaces, not switching machinery.
- **Storage keys on the data schema alone** (TODO §16.3), and resolved differently than planned: once IndexedDB shipped, its per-schema object stores **are** that layout, and `librept_db` is read exactly once as the legacy import source. A single plain key needs no bucket-keying scheme, so [`storageNamespace.js`](src/data/storageNamespace.js) dropped the release-tag axis and got no replacement. `CURRENT_SCHEMA_VERSION` stays a plain integer major — a "patch" to a schema is either a migration step or nothing.
- **The complexity gate lost its allowlist.** The last four `# noqa: C901` debt functions were fixed at source rather than carried; no pipeline gate may hold a mechanism for allowlisting real, unfixed debt.

## 2026-07-27 — Routing becomes a route table

### Added
- **The plan row you just touched survives a reload** — inserting or swapping a row in the inline editor now names it in the URL (`/session/{id}/client/{cid}/edit/exercise/{slotId}`). The call-out that highlights, scrolls to and focuses a fresh row was in-memory only, so a refresh mid-edit dropped the trainer into a long plan with nothing saying which row they were on. A **restored** row is deliberately not treated as a new one: it keeps the highlight and the scroll, but takes no caret (a reload must not pop the phone keyboard) and carries no *New* badge (nothing just happened to it). An id that no longer resolves is ignored and the segment drops, like a stale focus card. Covered by `test_editor_row_deeplink.py`.
- **[docs/ROUTING.md](docs/ROUTING.md)** — the routing architecture: the class hierarchy and the patterns it applies, specificity ordering, the `ctx` a route receives, the five invariants (no version in a path, patterns are additive, unknown routes 404 rather than redirect, URLs are built not spelled, no personal data in a path) and a checklist for adding a route. [UC5 §4](use_cases/uc5_session_day_deck_and_deep_links.md) stays the catalogue of *what* the URLs are.
- **The session's taxonomy picker is a route** — `/session/{id}/client/{cid}/edit/catalog`, and `…/catalog/slot/{slotId}` when swapping a specific row. A reload mid-browse reopens the picker over the restored editor instead of dropping the trainer back on the deck. The client id is already in the parent session URL, so this adds no new class of exposure.
- **The record editors are routes** — `/routines/new`, `/routines/{id}`, `/exercises/new` and `/adjustments/{updateId}`, each opening over its own list view. A routine link now opens that template's builder, a reload keeps the form (and its record) instead of dropping the trainer on a list, and Back backs out of the editor. Saving pops exactly one entry: the submit handler closes the dialog and the router turns that close into the matching pop, so Back after a save leaves the list rather than skipping a screen. Covered by `test_record_dialog_routes.py`.
- **Back closes a dialog** — About, Terms, build info and Sync & Backup are now routes (`/about`, `/terms`, `/build`, `/backup`), so the gesture a phone user already knows dismisses them, a reload reopens the one that was open, and the build stamp is a link a PT can paste into a bug report. The ✕, Cancel and Escape need no new wiring: `close` reaches a capturing listener even though it does not bubble, so one hook turns every existing close into the matching history pop. Arriving straight at a dialog URL synthesises the entry underneath it, so Back lands on the dashboard instead of leaving the app. The **first-run agreement is deliberately not routed** — it is a boot precondition, not a place the trainer navigated to, and Back must not dismiss an agreement that has not been accepted. Covered by `test_dialog_routing.py`.

### Changed
- **Routes resolve through a registry instead of a 27-branch `if/else`** — each addressable state is now a `Route` object owning its own pattern *and* what entering it does ([`routes/`](src/controllers/routes/routeTable.js)), and [`routerController.js`](src/controllers/routerController.js) only resolves and delegates. Three things the chain got wrong are structurally gone: the header/overlay lines that were copy-pasted into nine branches live once in the base class; `/session/new` outranking `/session/:sessionId` is now a property of the patterns (**literal segments win**) rather than of where a human wrote the branch; and a route no longer reaches for `document`, so routing is exercisable against stubs. Reverse routing (`urlFor`) makes a hand-spelled path unnecessary — which is what keeps patterns **version-agnostic**, since none of them ever sees the base path. Behaviour is unchanged, including the legacy `…/superset/{id}` focus spelling and the not-found view keeping the failed path in the address bar.

### Fixed
- **The session stopped overwriting its own dialogs' URLs** — the clipboard rewrites the address bar to whatever card is in focus on every render, guarded by two path-prefix tests that only ever excluded `/session/new` and `/session/setup/`. Every later route slipped through, so opening the taxonomy picker and typing one character erased the picker's URL. The sync now asks the router which route is active, and stands down entirely before the first route is entered — recovery renders at boot, ahead of routing, and a write there would erase the deep link the router is about to read ([`activeSessionController.js`](src/controllers/activeSessionController.js)).
- **A background re-render no longer bounces the URL off what the trainer is looking at** — the day deck reflected its focused day in the address bar whenever the dashboard redrew, guarded only by a "path does not start with `/session/`" test. Any other route slipped past it, so syncing from the Sync & Backup dialog pushed `/sessions/{date}` over the dialog's own URL and left Back reopening it. The guard now asks the router which route is actually active ([`daySelector.js`, since renamed `sessionTimeline.js`](src/modules/sessionList/sessionTimeline.js)); covered by `test_a_background_render_does_not_clobber_an_open_dialog`.
- **Tapping the build stamp no longer also navigates home** — it sits inside `#logo-area`, whose click goes to the dashboard. Harmless while the dialog merely opened on top; now that it is a route, the stray navigation closed it again ([`buildInfoDialog.js`](src/modules/common/buildInfoDialog.js)).
- **The build gate fixes formatting instead of printing a diff** — both lint steps checked without applying, so a run ended by asking a human to re-apply whitespace by hand and re-run the whole gate (which is what produced `c3cc369`). Ruff and Biome now write those fixes and the stage **names every file it rewrote**; findings that need a human decision are untouched, and the re-check without `--write` is still the verdict ([`build/__init__.py`](build/__init__.py)).

## 2026-07-27 — Data layer: record identity, IndexedDB engine, and schema projections

First steps of the star-write architecture (TODO §18): a data layer that writes every record to
all supported schema versions at once, so moving between app versions loses nothing either way.

### Added
- **Record identity moved to UUIDv7** ([`recordId.js`](src/data/recordId.js)) — 122 bits of
  collision resistance plus lexicographic time-ordering, replacing a 41.4-bit `Math.random`
  generator that carried a 1.38% chance of at least one collision over five years of a very busy
  PT's records. All call sites switched to `newRecordId()`. **Decided (TODO §18.2, closed):**
  identity is the record's own `id` acting as a `lineageId` — no separate old-id→new-id mapping
  table; a set-difference completeness check gives migration the same guarantee a mapping table
  would have, at no extra storage cost.
- **IndexedDB engine, parts 1-3** — [`indexedDb.js`](src/data/indexedDb.js): one database, one
  object store per schema, transactions that resolve on commit, collection + client indexes
  (including a compound `byClientAndCollection` index for per-client queries).
  [`storageDurability.js`](src/data/storageDurability.js): requests eviction-proof storage on boot,
  reports risk by measuring the consequence (quota, `persist()`) rather than sniffing for private
  browsing. [`writeQueue.js`](src/data/writeQueue.js): write-behind persistence — reads stay
  synchronous against in-memory state, writes serialise through a queue. None of this is wired into
  `stateStore` yet (still on localStorage); this is the engine the eventual swap will run on.
- **Schemas exist as data** — [`recordSchemas.js`](src/data/recordSchemas.js) declares the current
  schema's per-collection field shapes, and [`recordProjections.js`](src/data/recordProjections.js)
  projects each live domain object into it, proven against real seed data and the actual object
  literals live writers build (not an idealised model), in `test_record_schemas.py`. This is the
  single-schema half of TODO §18.4's staging guard; the fan-out into an actual IndexedDB bucket and
  the cross-schema half both wait on a second live schema existing.

- **More exercise types & cardio metrics** (extends TODO §13.3) — the modality axis gains **isometric** (a hold *under load* — weighted plank, wall sit, overhead hold) and **agility** (speed/coordination drills logged in time / distance / reps), and cardio gains **pace** (min/km) and **heart-rate** (bpm) metrics. The load axis is now decided centrally by `usesLoad` (strength + isometric carry load; cardio, holds, agility don't), and the custom-create metric selector is populated per modality. Seed movements added for each; covered by `test_exercise_modality.py`. Brings coverage in line with the recognised health- + skill-related fitness components ([UC6 §5](use_cases/uc6_exercise_taxonomy_and_picker.md)); only HIIT/rounds remains reserved-but-unbuilt.
- **Structured session history** (TODO §17.1) — a finished session now persists the **whole program** as an immutable snapshot ([`sessionItemRecord.js`](src/domain/sessionItemRecord.js)), not just performed sets. History records store a flat list of typed items — exercises and first-class **rests** — with **superset grouping** (via `circuitId`, folded at render like the live deck) and a **completed** flag per exercise, so **prescribed-but-skipped** movements are kept (rendered greyed with a *Skipped* badge) instead of dropped. The History view renders superset groups, rest chips, greyed skips, and per-modality metrics; re-opening a past session rebuilds the full live plan (rests + circuits + modality) from the snapshot. Additive and back-compatible — legacy flat rows and the seed render unchanged behind a shape guard. Covered by `test_session_item_record.py`; the demo dataset gains a structured record + cardio/balance/stretch cards in the demo session.
- **Exercise modalities** (TODO §13.3 / the modality field of §17.1) — a movement is no longer always sets × reps × load. Each carries a **modality** ([`exerciseModality.js`](src/domain/exerciseModality.js)): **strength** (default), **cardio** (logged against **time / distance / calories / watts** — assault bike, rower, ski-erg, watt bike, treadmill), and **stretch** / **balance** (a **hold-time**). Like reps/load, the raw target is stored on the item and its meaning derived at render, so routines/sessions/history need **no migration**. The focus card, compact row, past-session peek, plans preview and history log show the right unit and drop the load tile for non-strength work; the focus timer seeds the target duration for time-bound cardio/holds. Custom-create gains a modality selector (cardio also picks its metric); the catalog and picker flag non-strength movements with a highlighted modality badge. Covered by `test_exercise_modality.py`; documented in [UC6 §5](use_cases/uc6_exercise_taxonomy_and_picker.md).

### Changed
- **OWASP ZAP is now a real, enforced build gate.** It previously ran without host networking (so it reached nothing → exit 3) and swallowed every non-zero exit as success. Now the container runs with `--network host` so it truly scans the app, the dev server serves real security headers (CSP-as-header, Permissions-Policy, Referrer-Policy, COOP, scrubbed `Server`), `script-src` drops `'unsafe-inline'` (the theme bootstrap moved to [`theme-boot.js`](src/theme-boot.js); two inline `onclick`s became delegated listeners), and a non-zero ZAP exit **fails the build**. Remaining alerts are triaged in [`deploy/zap/zap-baseline.conf`](deploy/zap/zap-baseline.conf) with written justifications — result: `FAIL-NEW: 0, WARN-NEW: 0`. Codified as a squeaky-clean-builds rule in [AGENT_RULES.md §2.A.3](AGENT_RULES.md).

## 2026-07-23 — Fixes

### Fixed
- **Late-evening session cards silently failed to launch.** The demo generates session times relative to now, so after ~21:00 a live session's range crossed midnight (e.g. `"22:00 - 00:00"`); `parseTimeRange` read it as inverted (`end < start`), so `isTimeOverlapping` matched nothing — not even itself — `getOverlappingBookings` returned `[]`, and clicking the card did nothing. `parseTimeRange` now treats an end at/before the start as crossing into the next day. This was exposed when the 18:00 demo-hours clamp was dropped (TODO 1.4). Guarded by a clock-mocked regression test (`test_session_launch_time_of_day.py`) so it's no longer time-of-day dependent.
